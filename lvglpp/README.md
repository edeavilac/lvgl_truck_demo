# lvglpp

The C++ binding of the LVGL in [`../lvgl`](../lvgl), generated by
[cpp-binding](https://github.com/edeavilac/cpp-binding). It is header-only and needs C++20:
include `lv/lvgl.hpp` and link `lvgl`. The `lvglpp` CMake target does both.

Everything under `lv/` is generator output. Do not edit it by hand. Regenerate it instead
(see below).

## Where it comes from

| | |
|---|---|
| Generator | cpp-binding `bda76a5`, branch `claude/cpp-binding-v9-example-ngbn1b` |
| Profile | `config/profiles/lvgl-9.6.0.yaml` |
| LVGL | 9.6.0-dev `4170bcb`, the commit this repository's `lvgl` submodule points at |

## What is in it

These counts come from the generator's report, `docs/regresion/generacion-9.6.0.txt` in
cpp-binding:

- 176 headers and 30 748 lines;
- 118 classes (55 of them derive from another), 1 316 methods and 614 free functions;
- 156 enums, 431 style properties and 72 typed event codes;
- all 2 398 C functions in the model are wrapped.

The tree compiles with `-Wall -Wextra` and no diagnostics, both with LVGL's defaults
(`LV_CONF_SKIP`) and with this demo's `lv_conf.h`. It does not need `LV_USE_PRIVATE_API`.
The generator turns that option on only to read the widget structs.

## Using it

```cpp
#include "lv/lvgl.hpp"

void build()
{
    lv::Button button = lv::Button::create(lv::display_screen_active());
    button.style(lv::Part::Main).bg_color(lv::Color::white()).radius(8);
    button.on(lv::events::Clicked, [](auto &) { LV_LOG_USER("clicked"); });

    lv::Label label = lv::Label::create(button);
    label.set_text("Open All");
}
```

Every wrapper hands its C object back through `raw()`, so anything the binding does not
cover can still be called in C. [`../ui/src/lv_demo_truck.cpp`](../ui/src/lv_demo_truck.cpp)
shows the rest in practice: `lv::Anim` with a typed exec callback, `lv::SubjectOf<T>` and its
observers, and closures on events.

Known gaps, found while porting the demo:

- **Function-like macros** such as `LV_PCT`, `LV_SIZE_CONTENT` and `LV_RADIUS_CIRCLE` are
  still C.
- **Free function names are module + tokens.** So `lv_pct` is `lv::area_pct` and
  `lv_screen_active` is `lv::display_screen_active`.
- **`lv_opa_t` is a `uint8_t`.** The opacity setters take it raw, and `lv::OpacityLevel`
  needs a `static_cast`.
- **The glTF viewer is free functions**, as in `lv::gltf_set_yaw(viewer, ...)`. The reason
  is that `lv_gltf_class` is not exported and the viewer's struct is C++, so there is no
  checked class to build.
- **`struct _lv_display_t *` stays raw in 4 crossings**, `Indev::set_display` among them. It
  is the other spelling of the display handle.
- **`LV_EVENT_TRANSLATION_LANGUAGE_CHANGED` has no typed tag**, because its enumerator only
  exists under `LV_USE_TRANSLATION`. With translation on, register it by code:
  `obj.on(lv::EventCode::TranslationLanguageChanged, f)`.

## Regenerating it

You need JDK 25 and Maven. The profile reads LVGL from `../lvgl/LVGL-v9.6.0`, relative to the
cpp-binding clone:

```bash
git clone -b claude/cpp-binding-v9-example-ngbn1b https://github.com/edeavilac/cpp-binding
git clone https://github.com/lvgl/lvgl lvgl/LVGL-v9.6.0
git -C lvgl/LVGL-v9.6.0 checkout 4170bcb

cd cpp-binding
git checkout bda76a5
mvn dependency:build-classpath -Dmdep.outputFile=target/cp.txt
./build-run.sh
java -cp "target/classes-run:$(cat target/cp.txt)" \
    cpp.binding.generator.cpp.CppMain config/profiles/lvgl-9.6.0.yaml --out build/lvglpp
```

`build/lvglpp/9.6.0/lv` then replaces `lv/` here. If the `lvgl` submodule moves, move the
LVGL checkout to the same commit first.
